# Great Kingdom AI

Great Kingdom AI는 9x9 추상 전략 게임 **Great Kingdom**의 규칙 엔진과 AlphaZero 계열 학습 루프를 구현하는 프로젝트입니다.

현재 코드는 다음을 포함합니다.

- Rust 규칙 엔진과 PyO3 Python extension
- Gumbel AlphaZero 스타일 tree search backend
- PyTorch policy-value network
- self-play replay 생성, replay buffer 저장/로드
- checkpoint 학습, resume, candidate-vs-best arena 평가
- end-to-end pipeline
- 로컬 CPU smoke config와 Runpod GPU config

규칙의 기준 문서는 [docs/rule-spec.md](docs/rule-spec.md)입니다.

## Game

Great Kingdom은 두 플레이어가 번갈아 성을 놓으며 영토를 만드는 2인 게임입니다.

- 보드: 9x9
- 행동 공간: 82개
- `0..80`: 각 보드 칸에 성 놓기
- `81`: pass
- 중앙에는 중립 성 1개가 있습니다.
- 상대 성 그룹을 완전히 포위하면 즉시 승리합니다.
- 자신의 성 그룹이 파괴되면 즉시 패배합니다.
- 양 플레이어가 연속 pass하면 영토 점수로 승패를 판정합니다.

자세한 규칙은 [docs/rule-spec.md](docs/rule-spec.md)를 보세요.

## Search

검색은 Gumbel root sampling, root sequential halving, 내부 node deterministic selection, improved policy target을 사용하는 Gumbel backend로 고정되어 있습니다.

Gumbel backend는 replay policy target으로 visit count normalization이 아니라 `policy_target()`을 사용합니다. Self-play와 arena에서 실제 착수는 기본적으로 `selected_action()`을 사용합니다.

Gumbel 관련 주요 config:

```json
{
  "gumbel_simulations": 128,
  "gumbel_max_considered_actions": 16,
  "gumbel_c_visit": 50.0,
  "gumbel_c_scale": 1.0,
  "gumbel_seed": 2026,
  "sampling_temperature": 0.0
}
```

## Local Setup

Use Python venv locally.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

If you need PyTorch locally, install a CPU wheel unless this machine has a working CUDA setup.

```bash
python -m pip install --index-url https://download.pytorch.org/whl/cpu 'torch>=2.6'
```

Build the Rust extension into the venv.

```bash
cd rust/great_kingdom_core
python -m maturin develop
cd ../..
```

Run tests.

```bash
cargo test --manifest-path rust/great_kingdom_core/Cargo.toml
python -m pytest
```

If console scripts such as `great-kingdom-pipeline` are missing, either rerun editable install or use module execution:

```bash
python -m pip install -e '.[dev]'
python -m great_kingdom_ai.pipeline --help
```

## Smoke Tests

### CPU Gumbel Smoke

The CPU configs are small and suitable for a laptop.

```bash
python scripts/run_m8_train_smoke.py \
  --config configs/test/gumbel/cpu/train-smoke.json \
  --work-dir data/test/gumbel/cpu-train-smoke \
  --device cpu \
  --allow-cpu
```

```bash
python -m great_kingdom_ai.pipeline \
  --pipeline-config configs/test/gumbel/cpu/pipeline-smoke.json \
  --train-config configs/test/gumbel/cpu/train-smoke.json \
  --arena-config configs/test/gumbel/cpu/arena-smoke.json \
  --device cpu \
  --json
```

Arena smoke needs candidate and best checkpoints. You can reuse the checkpoint generated by the train smoke.

```bash
python -m great_kingdom_ai.evaluate \
  --config configs/test/gumbel/cpu/arena-smoke.json \
  --candidate data/test/gumbel/cpu-train-smoke/checkpoint.pt \
  --best data/test/gumbel/cpu-train-smoke/checkpoint.pt \
  --report data/test/gumbel/cpu-arena-report.json \
  --device cpu
```

## Runpod

Target training environment:

```text
runpod/pytorch:2.4.0-py3.11-cuda12.4.1-devel-ubuntu22.04
RTX 3090 24GB
```

On a fresh pod:

```bash
./scripts/setup_runpod.sh
source .venv/bin/activate
python scripts/run_m6_smoke.py
python scripts/run_m8_train_smoke.py \
  --config configs/test/gumbel/gpu/train-smoke.json \
  --device cuda
```

Run the Gumbel training pipeline:

```bash
python -m great_kingdom_ai.pipeline \
  --pipeline-config configs/runpod/gumbel/pipeline-runpod.json \
  --train-config configs/runpod/gumbel/train-runpod.json \
  --arena-config configs/runpod/gumbel/arena-runpod.json \
  --device cuda
```

Start a fresh run with a separate output directory:

```bash
python -m great_kingdom_ai.pipeline \
  --pipeline-config configs/runpod/gumbel/pipeline-runpod.json \
  --train-config configs/runpod/gumbel/train-runpod.json \
  --arena-config configs/runpod/gumbel/arena-runpod.json \
  --device cuda \
  --fresh \
  --work-dir data/runpod/gumbel-YYYYMMDD
```

The pipeline writes replay, checkpoints, arena reports, and metrics under `work_dir`.

```text
work_dir/
  replay/replay.npz
  replay/game_logs.json
  checkpoints/best.pt
  checkpoints/candidate.pt
  checkpoints/candidates/candidate-000001.pt
  reports/metrics.jsonl
  reports/arena/
```

## Development Notes

- Local development assumes no GPU.
- Python should run inside `.venv`.
- Runpod should use the provided PyTorch image and CUDA package stack.
- Rust owns the game rules. Python should not duplicate rule logic.
- Do not add tactical heuristics to the search backend. Terminal outcomes come from the rules engine.
